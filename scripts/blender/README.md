# Blender scenes

Original 3D assets for Diego's portfolio, all generated by script in Blender 5.2.1
from editable primitives and curves. No downloaded models, textures, HDRIs or
film assets are involved; every `.blend` can be opened and edited by hand.

| Scene | Script | Output | Used by |
| --- | --- | --- | --- |
| Curiosity studio (headphones, books, record, pen, winged orb) | `create_studio.py` | `curiosity-studio.glb` · `studio-hero.png` | Home hero (`CuriosityHero.jsx`, live 3D) and the "turn it around" dialog |
| Turntable (belt-drive deck, S-curve tonearm) | `create_turntable.py` | `turntable.glb` · `turntable-hero.png` | The listening room, embedded inline in the page (`TurntableModel.jsx`) |
| Highland crossing (viaduct, scarlet express, imported castle) | `create_hogwarts.py` | `highland-crossing.glb` (Draco) | The opening of the page (`HighlandCrossing.jsx`, pinned; scroll dollies the camera toward the castle) |
| Diego avatar (Kangol, glasses, burgundy overshirt, standing wave) | `create_diego_avatar.py` | `diego-avatar.blend` · `diego-avatar.glb` · `diego-avatar-3d.png` | `/me.html` header (`DiegoAvatar.jsx`, drag or use the rotation buttons) |

The castle in the highland scene is **"castle 1234" by Felix Stief** (`assets/castle-1234-felix-stief.glb`,
Diego's download) — the script cuts away its display slab and stray scenery, keeps the rocky mound,
recolours it into the night palette, samples its walls to place ~170 lit window panes, and sets it on
the summit of a sheer crag rising straight out of the loch at the east end of the viaduct. The line
enters that crag through a tunnel portal directly under the castle (arch crown ≈ 11.45, above the
train's funnel cap at ≈ 10.4). The bore is real: it is carved out of the terrain, the castle mound and the
faceted headwall lumps (`carve`, `in_bore`), lined with an inward-facing near-black tube, floored, railed
and lit by faint wall lamps, and it ends at `TUNNEL_END` with the whole train inside (the web run stops
at x = 20). `-- --preview --tunnel out.png` renders a look into it from the deck. `CASTLE_X/Y/Z` (crag summit), `CASTLE_SCALE`, `CASTLE_YAW`, `PORTAL_X` and `MOON_AT` are the
knobs. `WEB_CAMERA` mirrors `SHOT.wide` in `HighlandCrossing.jsx`; run the script with
`-- --preview /path/out.png` for a quick Eevee still from that exact framing without exporting.

`common.py` holds the shared primitive factory, material helper, group joining and
GLB export. Everything is written to `public/models/` and `public/images/`.

## Building

From the repository root:

```sh
BLENDER=/Applications/Blender.app/Contents/MacOS/Blender
$BLENDER --background --factory-startup --python scripts/blender/create_studio.py
$BLENDER --background --factory-startup --python scripts/blender/create_turntable.py
$BLENDER --background --factory-startup --python scripts/blender/create_hogwarts.py
$BLENDER --background --factory-startup --python scripts/blender/create_diego_avatar.py -- --render
```

The turntable and highland scripts export the GLB in a few seconds. Add `-- --render`
to also produce the Cycles still (about a minute each on CPU):

```sh
$BLENDER --background --factory-startup --python scripts/blender/create_turntable.py -- --render
```

Each script saves the `.blend` *before* it collapses objects into web groups, so the
source file keeps every individual part, modifier, light and camera.

The avatar uses modeled geometry for the face, blue eyes, clear glasses, beard,
Kangol embroidery, clothes, and shoes. It is a static 3D mesh that visitors can
rotate; it is not rigged for skeletal animation. `diego-avatar.json` records its
bounds and export statistics. The viewer frames it automatically and renders on
demand. Its PNG is a transparent Blender render used while loading and if 3D
cannot load. To make a quick draft without replacing the final files:

```sh
$BLENDER --background --factory-startup --python scripts/blender/create_diego_avatar.py -- --quick --preview /tmp/diego-avatar-draft.png
```

## How the web runtime drives the models

Each exported GLB is a flat list of named meshes. Parts that move are exported with
their **origin at their pivot**, so the React components only rotate or translate a
node — no re-centring at runtime.

**`turntable.glb`** (units match the Three.js scene one-for-one)

- `Platter` — origin at the spindle; `rotation.y` spins it.
- `Tonearm` — origin at the bearing; `rotation.y` swings it, `rotation.z` (negative)
  lifts the stylus. Swing angles for park / lead-in / mid-groove are solved from the
  arm geometry and stored in `turntable.json` (`tonearmSwingRadians`). The deck uses
  real 9" proportions: effective length ÷ pivot-to-spindle ≈ 1.07.
- `Cue lever`, `Button 33`, `Button 45`, `Start stop`, `Status led`, `Cue led` —
  separate so the runtime can light or click them. LED materials carry emission.
- `Plinth`, `Tonearm base`, `Tonearm rest`, `Dust cover hinges` — static.

**`highland-crossing.glb`**

- `Train` — origin on the rails at x=0; the opening drives `position.x` from west to
  east. Steam is emitted from `funnelMouthYUp` in `highland-crossing.json`.
- `Castle`, `Cliff`, `Viaduct`, `Track`, `Terrain`, `Pines`, `Moon` — static. The `Lake` mesh
  is hidden at runtime and replaced by a reflective plane.
- Emissive materials (`Lit castle window`, `Carriage glass`, `Carriage lamp`) are
  flickered by the runtime. The file is Draco-compressed (`export_glb(..., draco=True)`);
  `useGLTF(url, true)` fetches the decoder on demand.

**`curiosity-studio.glb`**

- Six groups (`Headphones`, `Book — stories`, `Book — observations`, `Record`,
  `Golden flight`, `Fountain pen`). On the home page each one floats on its own
  spring-damper orbit (`src/utils/antiGravity.js`) and the record spins on hover.

The GLBs use glTF's Y-up convention (`export_yup=True`): a Blender point `(x, y, z)`
becomes `(x, z, -y)` on the web. Provide a studio environment map for the metallic
materials — the app generates one with `RoomEnvironment` (see `StudioEnvironment.jsx`),
so nothing is downloaded at runtime.
